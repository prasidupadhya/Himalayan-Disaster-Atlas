# Secret and browser boundary

No configuration secret is needed by Foundation. The attachment supplied outside Git contains private acquisition credentials; it is not a repository input or browser asset. Keep future credentials in the shell of an offline acquisition job or a dedicated ignored pipeline-only environment file, never in web configuration, public assets, fixtures, Git, URLs or logs. The foundation pipeline does not automatically load any environment file.

`npm run build` strips inherited environment variables to a minimal OS allowlist before Next.js runs. It rejects environment files anywhere inside `apps/web`, private-key file containers, symlinked publishable source, recognizable credential patterns, and any known private token values in the current shell that appear in source or output. It checks both before and after the build without printing detected values. `.gitignore` excludes local env files and raw/intermediate data. Browser code cannot read `process.env` or import private pipeline/raw-data modules under ESLint rules. No `NEXT_PUBLIC_*` variables are needed or supported. No remote acquisition URLs are read by the browser loader; it accepts only versioned local data paths.

These are layered safeguards, not a mathematical guarantee that every arbitrary hardcoded secret can be detected. Review diffs and public metadata before release. Do not invoke the workspace's raw `next build` command to bypass the root security gate. Future deployment CI should require the root gate and add a dedicated secret scanner, dependency auditing and host security headers. Only the static `apps/web/out` directory is a deployment artifact. Credential rotation is managed outside this repository.
