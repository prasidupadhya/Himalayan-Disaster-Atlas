# Feature 43 — open live feeds

Depends on Feature 42. Acquisition is an offline/local Python runner and a **workflow_dispatch-only** GitHub Action. No cron, browser acquisition, main-branch bot, DHM/BIPAD ingestion or automatic data deployment is enabled. The Data Catalog delivery inspector reads same-origin, validated static JSON. This is periodically updated conditions, not a warning service.

## Sources and scope

USGS [GeoJSON interface](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php) and [licensing guidance](https://www.usgs.gov/data-management/data-licensing): seven-day regional earthquake query, longitude 80–89 / latitude 26–31. Preserve preferred magnitude type, zero/null, event time, revision time, preferred network and event URL. Only preferred network `us` summaries are retained under this review; other preferred networks are withheld. Empty means no retained records in this query, never no earthquakes/all-clear. A response at the 500-record cap fails rather than claiming completeness. Records are REPORTED epicentres, not shaking or impact footprints.

NOAA/NCEP [GFS product](https://www.nco.ncep.noaa.gov/pmb/products/gfs/nomads/) and [NWS data terms](https://www.weather.gov/disclaimer): native 0.25° grid, surface APCP, one six-hour accumulation at cycle +18 to +24 hours. Select a 00/06/12/18 UTC cycle with five hours of publication lag. Decode [GRIB2 template 4.8](https://www.nco.ncep.noaa.gov/pmb/docs/grib2/grib2_doc/grib2_temp4-8.shtml), verify centre/operational forecast, grid, parameter, units, cycle and encoded interval. The shorter six-hour field is selected explicitly if a cumulative field accompanies it. Water-equivalent kg/m² converts exactly to mm. GDAL/Rasterio decode retained native grid values; masked values remain null. There is no interpolation, daily total, anomaly, local warning or ensemble uncertainty claim. Product, cycle, generating-process identifier and raw hash pin the revision; an exact operational solver build is UNKNOWN.

`licensing/live-sources.json` is the trusted external source review. A source's own PERMITTED field cannot grant rights. Exact source identity and contributor/product restrictions are checked independently in Python, Node release validation and browser loading. USGS credit and NOAA credit/no-endorsement/transformation notices remain visible. No upstream imagery or third-party products are covered by these reviews.

## Bounds, time and failures

Two requests per run, maximum 2 MiB each, 20-second socket timeout and 45-second bounded transfer window; redirects and unapproved hosts fail. No eager retries. Normalized snapshots stay below 512 KiB; index below 64 KiB. HTTP/network/timeout/invalid-data failures have distinct error codes. Malformed JSON, empty HTTP bodies, truncated collections, HTML instead of GRIB and missing expected fields fail. A structurally valid empty USGS collection succeeds. The documented USGS `nodata=204` response also succeeds with empty records; its source generation time is UNKNOWN, so freshness remains STALE rather than fabricated from fetch time. An empty HTTP 200 body still fails. Missing values stay UNKNOWN; source zero stays zero.

Freshness uses USGS collection generation (6-hour threshold) and GFS issue cycle (12-hour threshold, shortened by validity expiry), never the acquisition clock. Each record keeps observation or issue/validity times. The workflow's heartbeat becomes STALE after six hours independently of source time; its 10,800-second target cadence is metadata only, **not an active schedule**. Failure retains the last verified snapshot as STALE; absent snapshot is UNAVAILABLE. Corrupted bytes are never displayed. Original successful-fetch timestamps survive failure. The browser rechecks time after tab resume.

## Publication decision

Recommended and implemented: **dedicated `live-data` branch**, containing only `live/latest.json`, immutable history indexes and `/data/live-<feed>/<version>/{snapshot,manifest}.json`. No source code is executed from that branch. Concurrent publication is serialized. Whole immutable directories stage and rename on the same filesystem; checksums, semantics and exact source review pass before a final fsync/replace of the latest pointer. Conflicting published bytes fail. The branch push promotes the complete git transaction atomically. The branch retains immutable evidence; a static deployment includes only the latest index plus at most eight history indexes and their referenced releases (64-file cap). Archive the acquisition branch separately before its 10,000-file restore cap; never reuse a version URL.

A static build can pin a full data commit with `ATLAS_LIVE_DATA_COMMIT=<40-hex-SHA> npm run build`. The root build fetches only live-data, imports a bounded allowlisted file set without executing branch code, validates contracts/semantics/rights/hashes, then generates the usual tested public inventory. Release checks repeat live validation against trusted checked-in policy. Dynamic live artifacts have this separate exact-byte ledger, not an exemption from rights checks. Existing public/research exclusions remain unchanged. Without a pin, an explicit unconfigured index is published; no readings/fetch success are fabricated. The source code policy registration `atlas-live-open-feeds@1.0.0` and `atlas-provenance@1.3.0` contain original MIT metadata only. Exact live release manifests provide each snapshot's source request, raw hash, processing version, review evidence, obligations and snapshot hash.

Alternatives: commits to main would couple noisy time-series history to software review and violate the no-main-bot decision. Build-time upstream acquisition would mix nondeterministic availability with software release checks and require fresh provider requests on every build. A dedicated branch separates acquisition from software, permits pinned reproducible Cloudflare exports and works without a runtime API. Trade-off: publication is not visible until a new static deployment imports the new commit. The UI shows actual source/fetch/workflow timestamps, so that lag cannot masquerade as current data. Git data history also grows; bounded static history is not archive garbage collection.

The manual Action restores the previous data branch, runs the same local runner, publishes only to live-data and reports the resulting data SHA. It does not commit to main, alter Cloudflare settings, deploy or enable a scheduler. Pin that SHA in the Cloudflare build configuration or run the root build locally. The existing quality workflow remains deterministic and unconfigured by default. A future reviewed scheduler proposal is `cron: '17 */3 * * *'`; it is deliberately absent from YAML. Review hosting refresh, quotas and deployment trigger policy before activation.

## Reproduction and maintenance

`npm run live:fetch` writes ignored `data/live-publication`; retained raw source bytes go to ignored `data/raw/live`, identified by hash. `--output` chooses an isolated local transaction directory. Do not expose raw provider bodies or credentials. The root build strips acquisition environment variables before rendering. `packages/contracts/generated/live-runtime.cjs` compiles the exact TS semantics offline for Node gates; generation is checked alongside standalone schema validators, preserving strict CSP and Python/TS parity.

Tests use explicit synthetic USGS values and a hash-pinned archived NOAA GRIB decoder fixture (see `tests/fixtures/live-open-feeds/gfs-source.json`); neither is published as current data. Python covers interval/grid/null/zero, malformed/empty/failed, retained snapshots, corrupt prior releases, reviewed terms, immutable conflict and pointer staging failure. Vitest covers Node/TS/Python contract agreement, exact source policy, corrupted/absent/oversized delivery and inactive scheduling. Playwright covers normal, empty, failed, unavailable, stale, corrupt/retry, no-WebGL/mobile and keyboard-only delivery.

Before PR: `npm run check`, `npm run test:e2e:public`, `npm run release:check`. Review source interface and terms changes through a new source policy version; old immutable releases are not silently relicensed. Physical inundation, destroyed buildings, casualties, repair costs, hydropower downtime and economic loss remain UNKNOWN. [DHM](https://www.dhm.gov.np/index.php), [NDRRMA](https://ndrrma.gov.np/) and [BIPAD](https://bipadportal.gov.np/) remain official warning authorities.
